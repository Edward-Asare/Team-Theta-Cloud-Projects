#  Team Theta Portfolio — Serverless Static Website on AWS

A fully serverless, highly available static website deployment using **Amazon S3**, **CloudFront**, **ACM**, and **Route 53** — built as part of the **Cloud Build with Peers** cohort 1.

Live domain: [`teamtheta.site`](URL) (and [`www.teamtheta.site`](URL))

---

##  Architecture

```
User Browser
     │
     ▼
Route 53 (DNS - Alias Record)
     │
     ▼
CloudFront Distribution (HTTPS, ACM Certificate)
     │  (Origin Access Control)
     ▼
S3 Bucket (Private, static files)
```

**Key design principle:** the S3 bucket stays 100% private. Nothing is public-facing except the CloudFront distribution, which is authorized to read from S3 via **Origin Access Control (OAC)**. This is the current AWS-recommended pattern for static site hosting — it's more secure than the older "public bucket + static website hosting" approach.

##  Step-by-Step Build

### Step 1: Create a Private S3 Bucket
- Created a bucket (e.g. `teamtheta-portfolio-storage`) with a unique name — it doesn't need to match the domain since CloudFront sits in front of it.
- Kept **Object Ownership** as *ACLs disabled* and **Block all public access** turned **ON**.
- Uploaded the site files, making sure `index.html` sits at the bucket root.

### Step 2: Request a Free SSL Certificate (ACM)
- Switched the console region to **US East (N. Virginia) — us-east-1**. This is required — CloudFront only accepts ACM certificates issued in this region, regardless of where your other resources live.
- Requested a public certificate for:
  - `teamtheta.site`
  - `*.teamtheta.site` (covers subdomains like `www`)
- Used **DNS validation** and clicked **Create records in Route 53** to auto-insert the validation records.
- Certificate status flipped from `Pending` → `Issued` within ~10 minutes.

### Step 3: Create the CloudFront Distribution
- Origin domain: selected the S3 bucket directly.
- Origin access: set to **Origin access control settings (recommended)** and created a new OAC with default settings.
- Viewer protocol policy: **Redirect HTTP to HTTPS**.
- WAF: **Do not enable security protections** — avoids extra charges for a small learning/portfolio project.
- Alternate domain names (CNAMEs): `teamtheta.site` and `www.teamtheta.site`.
- Attached the ACM certificate from Step 2.
- Default root object: `index.html`.

### Step 4: Authorize CloudFront to Read S3 (the OAC bridge)
- After creation, CloudFront shows a banner: *"The S3 bucket policy needs to be updated."*
- Copied the auto-generated policy from that banner.
- Pasted it into the S3 bucket's **Permissions → Bucket policy**.
- This grants CloudFront (and only CloudFront) read access to the private bucket.

### Step 5: Route Domain Traffic via Route 53
- In the Hosted Zone for `teamtheta.site`, created an **A record**:
  - Record name left blank → routes the root domain.
  - Toggled **Alias** ON → **Alias to CloudFront distribution**.
- Repeated with record name `www` so `www.teamtheta.site` resolves the same way.

##  Key Takeaways

- **Never make the S3 bucket public** — OAC + a bucket policy generated by CloudFront is the modern, secure pattern.
- **ACM certificates for CloudFront must live in `us-east-1`**, no exceptions, even if your other resources are elsewhere.
- **Alias records** in Route 53 are the AWS-native way to point a domain at CloudFront/S3/ELB — and they're free, unlike standard CNAMEs.
- Disabling WAF is a reasonable trade-off for a low-traffic portfolio site to avoid unnecessary charges — worth revisiting if the site ever needs to handle production/public traffic at scale.
